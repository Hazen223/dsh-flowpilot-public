## 1. 产品与设计目标

FlowPilot 把「业务线 → 项目 → 流程实例 → 节点」的推进模型放进 DeepSeek Harness 的主面板。
UI 的第一目标不是"好看"，而是**让今天该做什么一眼可见、让推进动作一步可达**：

| 目标 | 设计含义 |
|---|---|
| 一眼看到状态 | 用灰阶面 + 少量语义色分层，不做装饰性视觉 |
| 一眼看到动作 | 每个区域只有一个主操作；其它动作退后但可辨认 |
| 少读字 | 能用布局/图标/状态表达的，不写第二个标签 |
| 不打断 | 推进、确认、归档等操作就地完成，少跳转、少弹窗 |
| 可排障 | 版本/同步/数据状态可查，错误提示给"下一步怎么做" |

## 2. 设计原则（8 条，按优先级）

1. **布局优先于文字。** 层级、位置、间距能表达的，不写解释性副标题。布局本身就在解释。
2. **用灰阶面分层，不用描边。** 底 → 卡 → 嵌块 → 控件是四档「面」；容器/按钮/输入框不画 border。
3. **4px 栅格。** 间距只允许 0/4/8/12/16/20/24/32/40；圆角/字号走固定档位。
4. **一个主操作。** 一个视图/卡片里只有一个强调按钮；其它动作中性化，靠尺寸/位置区分。
5. **中性优先，强调克制。** 黑/白是主色；紫色只是业务主题色，用于状态、选中、进度，不用于大面积填充。
6. **状态 = 颜色 + 形状 + 文字。** 不能只用颜色表达状态（色弱/深色模式都可读）。
7. **动效只表达状态变化。** 不做内容入场动画；只做宽度/颜色/浮层的过渡，且尊重 `prefers-reduced-motion`。
8. **可达性是基线。** 键盘可达、焦点可见、对比度达标、点击目标 ≥28px（主要按钮 32/40px）。

## 4. 设计令牌（Design Tokens）

全部定义在 `src/client/10-util.js` 的 `CSS_BASE`，用 `light-dark(浅, 深)` 承载双模式；其它文件只用 `--fp-*`，禁止 HEX / `--dsw-alias-*` 颜色。

### 4.1 颜色（面层级 = 设计的骨架）

| 用途 | 令牌 | 浅色 | 深色 |
|---|---|---|---|
| 应用底 | `--fp-base` | `#F6F7F8` | `#17181A` |
| 卡片 / 抬高面 | `--fp-surface` | `#FFFFFF` | `#1D1F23` |
| 下沉面 / 嵌块 / 控件 | `--fp-surface-2` | `#F1F2F3` | `#0D0E10` |
| 浮层 / 弹窗 | `--fp-overlay` | `#FFFFFF` | `#1D1F23` |
| 灰井（节点画布底） | `--fp-well` | `= surface-2` | `= surface-2` |
| 悬停 / 按下 | `--fp-hover` / `--fp-pressed` | `#F1F2F3` / `#E8EAEC` | `#24262B` / `#2A2C32` |
| 遮罩 | `--fp-mask` | `rgba(13,14,16,.44)` | `rgba(0,0,0,.62)` |
| 文本 1/2/3/4 级 | `--fp-text` … `--fp-text-quaternary` | `#0D0E10` / `#61666D` / `#9499A0` / `#B4B8BD` | `#F0F1F2` / 62% / 45% / 30% 白 |
| 主按钮填充/文字 | `--fp-brand` / `--fp-on-brand` | `#0D0E10` / `#FFF` | `#F0F1F2` / `#0D0E10` |
| 业务主题色 | `--fp-accent` / `--fp-accent-strong` | `#B753FF` / `#AD3BFF` | `#BB5CFF` / `#AE52F0` |
| 成功 / 警告 / 错误 / 信息 | `--fp-ok` / `--fp-warn` / `--fp-bad` / `--fp-info` | `#2AC864` / `#FFB027` / `#F85A54` / `#008AC5` | `#47CF79` / 同 / 同 / 同 |
| 阴影 1/2/3 | `--fp-shadow-1/2/3` | 黑 6/10/16% | 黑 36/46/56% |

**面的使用规则（最重要的一条）：**
```
--fp-base  →  --fp-surface   →  --fp-surface-2
（页面底）     （卡片，浮起）      （卡内嵌块/输入框，下沉）
```
> 卡片和它所在的分区**不能同色**，否则"卡片消失"；输入框和卡片**不能同色**，否则"控件消失"。
> 需要更多层级时继续在 `surface / surface-2 / well` 三档里选，不引入新颜色。

### 4.2 间距 / 圆角 / 字号 / 动效

| 类别 | 令牌 | 值 |
|---|---|---|
| 间距 | `--fp-sp-1..10` | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 |
| 圆角 | `--fp-radius-sm/md/lg/xl/pill` | 4 / 8 / 12 / 16 / 999 |
| 字号 | `--fp-font-xs/sm/md/lg/xl` | 11 / 12 / 13 / 15 / 19 |
| 动效 | — | 颜色/底色 140ms；宽度 200ms `cubic-bezier(0.22,1,0.36,1)`；弹窗 160ms；快捷面板 140ms |

- 卡片 `radius-lg`；输入/按钮/嵌块 `radius-md`；chip/开关/圆点 `pill`；
- 卡片内边距 16、卡内间距 12；列表行 `padding: 8px 12px`；
- **禁止** 6/10/14 圆角与 5/6/7/9/10/11/13/14/15/18/22/26 px 间距（audit 会拦截）。

## 5. 布局骨架

### 5.1 主面板（`main` 插槽）

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏（透明）：品牌 · 视图 tab · 节奏/汇总/同步/设置/时钟      │
├──────────┬───────────────────────────────┬───────────────┤
│ 左栏导航  │ 中栏（流程 / 今日 / 交接 / 周报）│ 右栏节点详情   │
│ 白卡     │ 内容卡直接浮在灰底上            │ 白卡          │
└──────────┴───────────────────────────────┴───────────────┘
```
- 面板底 = `--fp-base`，内容卡之间 12px 间隙，不画描边；
- 顶栏不画卡片，只放按钮与 28px 药丸 chip；
- 视图 tab 顺序固定：**流程 → 今日 → 交接 → 周报**（默认流程）；
- 左栏可折叠：只做 `flex-basis/width` 200ms 过渡，**不做内容入场动画**（避免折叠时闪烁/跳动）。

### 5.2 左栏导航

- 一张白卡；业务线分组（名称 + 数量 + 悬停出现的 `+`/编辑）；
- 项目条目为两行卡：`编号 chip + 标题` / `阶段 · 截止日`，底部 3px 进度条贴卡底；
- 第二行**不重复业务线名**（外层分组已经说明），阶段名足够；
- 行级状态：hover `--fp-hover`、选中 `--fp-surface-2 + shadow-1`；
- 右键菜单：项目条目 → 打开 / 归档或恢复 / 删除；业务线标题 → 新建项目 / 重命名 / **归档业务线（N 个项目）**；
- 底部常驻「**已归档 N**」栏目：展开列出归档项目，空态一行"没有已归档项目"；底部操作只剩 **AI 建流程**（新建业务线在首次引导卡与 AI 下拉里）。

### 5.3 中栏流程页

- **两张独立卡**：
  1. **项目信息卡**：业务线/项目名/截止/阶段 chip/操作/流程进度条；操作区贴右；
  2. **项目节点卡**：灰井（`--fp-well`）铺满整卡，节点卡浮在井上；已完成/锁定节点退后一档；
- 节点导轨：`32px` 宽的竖轨，标记为 **20px 正圆**（不是圆角矩形）；完成=浅绿底+绿勾；
- 连接线：1.5px、柔和灰（`border-strong 55% + text-quaternary`），虚线 4/9；回流边=橙色 62%、3/8 虚线；
- 画布右下角 **圆形 FAB（+）**：40px、中性面底（`--fp-surface`）+ 次级灰图标，不用强调色；展开菜单向上，卡片 `radius-lg`；
- 长内容滚动时，上下边缘用 **透明度遮罩渐隐**（mask-image），不用 blur。

### 5.4 右栏节点详情

- 一张白卡，卡内用 `--fp-surface-2` 灰面分组：双角色确认 / 推进节点 / 计划与跟进 / 关联链接 / 笔记；
- **推进节点**：只有「开始处理 / 继续修改」是主操作（实心），开始处理上方；「标记完成」「等待」「阻塞」「跳过」全部中性面按钮；
  - 灰色的分区底 + 默认按钮同色会导致"按钮消失"，所以详情分区内的 default 按钮底色要抬到 `--fp-surface`，hover 用 `--fp-pressed`；
- 计划与跟进：日期/时间输入统一 `.fp-dt-input`（清原生边框、surface 底、32px 高）；
- 审批日志：意见长文本换行（`overflow-wrap:anywhere`），时间/人名不挤掉状态；已完成节点**不显示逾期**。

### 5.5 顶栏 / 快捷面板

- 顶栏响应式：<1120px 收进「⋯」；<860px 品牌只留图标；
- 入口 chip = 28px 药丸（`surface-2`，无描边）；
- 快捷面板：372px 宽、`surface + radius-lg + shadow-3`、限高滚动；内部分组 `surface-2`；
- 快捷面板的「今日 / 交接」等跳转**必须真正切视图**：跨组件树用页面自定义事件（`flowpilot:set-view`）通知 Shell，不能只写 localStorage。

### 5.6 弹窗 / 设置页 / 只读网页

- 弹窗：`--fp-mask` 遮罩 + `--fp-overlay` 卡（`radius-lg`、`shadow-3`），不画描边，内容区独立滚动；
- **设置页 = 卡片墙**：
  - 弹窗 body = `--fp-surface-2`（灰底），每个功能一张 `--fp-surface` 卡（圆角 12、内边距 16、卡内间距 12）；
  - 卡内控件（input/select/textarea/chip/路径/链接）用 `--fp-surface-2` 再下沉一档；
  - 同步/版本面板也作为卡片承接；底部保存栏是一张卡；
- AI 建流程弹窗：一屏一条主线，状态压成一行（圆点 + 文字），字段头 = 标签 + 右侧字数，说明只在 footer 出现一次；
- 本地只读网页（`lib/webaccess.js`）：独立静态页、`prefers-color-scheme` 跟随深浅色、10s 自动刷新，不加载 DSH 前端。

## 6. 组件规则

### 6.1 按钮（层级 = 语义）

| 层级 | 用法 | 样式要点 |
|---|---|---|
| `primary` | **唯一主操作**（开始处理 / 保存设置 / 生成项目 / 解析 PRD） | 黑/白反转填充，字重 600；不要滥用 |
| `default` | 常规动作（标记完成、等待、阻塞、取消保存…） | `--fp-surface-2` 底，hover `--fp-hover`；在灰面分区内抬到 `--fp-surface` |
| `ghost` / `quiet` | 文字型次级动作（取消、复制链接、行内编辑） | 透明底，hover 出灰底 |
| `danger` | 删除类 | `bad` 12% 透明底 + `bad` 文字，不用红边框 |

- 所有 `<button>` 必须 `border: 0; appearance: none;`（否则深色模式出现"双圈"）；
- 图标不是必需品：文字已经说清楚就不要再加图标（如底部「新建业务线 / AI 建流程」已去图标）；
- 按钮高度：顶栏/chip 28px、行内 26–28px、常规 30–32px、FAB 40px。

### 6.2 输入控件

- FpInput / FpSelect / FpTextarea 统一 `surface-2` 底、`radius-md`、无描边；focus 用 2px 主题色光圈；
- **原生控件必须重置**：`input[type=date|datetime-local]` 要 `border:0; appearance:none`，背景用 surface，`color-scheme: inherit` 让日历图标跟随主题；
- 数字输入靠右/等宽数字（`tabular-nums`）；错误态用 `bad` 光圈 + 一行错误文案；
- 开关（`FpSwitch`）= pill 轨道 + 圆形滑块；开=主题色，关=`pressed`。

### 6.3 Chip / 徽标 / 状态

- 状态 chip：语义色 12% 透明底 + 语义色文字，无描边，`radius-pill`；
- 节点状态色：进行中/当前=accent，待确认=warn，阻塞/错误=bad，完成=ok（低饱和底），未解锁=`text-quaternary` + `pressed`；
- 编号 chip：等宽 10–11px、surface-2 底、16px 行高。

### 6.4 菜单 / 浮层

- 统一 `.fp-ctxmenu`：`overlay + radius-md + shadow-2`，无描边；item 高 32、hover `--fp-hover`；危险项 `bad` 文字；
- 位置：贴鼠标点、自动避让视口边缘；`mousedown` 外部点击/Esc/滚动/resize 关闭；
- 右键菜单同时支持键盘触发（`ContextMenu` 键 / `Shift+F10`），行内 ⋯ 按钮可并入同一菜单；
- 下拉/浮层用 `shadow-3`（大）、上下文菜单 `shadow-2`。

### 6.5 卡片 / 分区

- 页面卡：`surface + radius-lg`，内边距 16，卡间 12–16；
- 卡内分区：`surface-2 + radius-md`；分区内再嵌控件时控件用 `surface`；
- 列表行不加分隔线；需要极淡分隔用 `.fp-divider`（1px 背景条），不用 border；
- 进度条：3px 高、`pressed` 轨道 + accent 填充，贴卡片底边、下圆角与卡一致。

### 6.6 空态 / Toast / 加载

- 空态只回答"这里是什么"（`还没有业务线` / `还没有链接` / `选择一个项目`），操作交给旁边的按钮；
- Toast：成功=默认面、错误=`bad` 面；文案一句话，包含对象名；
- 加载：`fp-spinner`（唯一允许保留 border 的元素）；内容区不做骨架屏入场动画。

## 7. 文案与信息架构

### 7.1 核心原则

> **Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**
> （不写不必要的副标签和说明，让布局去解释。）

1. **同一信息只写一次。** 状态 chip 表达过的状态，不再写一行状态说明；
2. **能由布局/图标/按钮 label 表达的，不写 hint**；
3. **hint 只写约束或默认值**，不写"留空表示不设置"这类复述；**超过 30 个汉字视为过度解释**；
4. **空态只回答"这里是什么"**；
5. **数量用数字 + 单位**（`6 可推进`、`N 字`），不用整句；
6. **动作标签用动词开头**（开始处理 / 标记完成 / 归档业务线），状态标签用名词（设计中 / 验收中）；
7. **错误说"怎么修"**，不只说"失败了"。

### 7.2 正反例

| 反例 | 正例 |
|---|---|
| 标题 +「在这里管理你的项目」 | 只留标题（布局已经说明） |
| 输入框 hint「至少 20 字；可拖入 .md/.txt（仅本地读取）」×3 处 | 字段头右侧「N 字」；文件行右侧「仅本地读取」；footer 说一次「至少 20 个字才能解析」 |
| 每条状态 chip 下面再写「当前状态：xx」 | 只留 chip |
| 「解析只生成提案，不写入数据」在标题/横幅/正文/footer 各写一遍 | 只在 footer 写一次 |
| 「（可选）」出现在每个可选字段 | 去掉；真正需要的约束写在 hint 里 |
| 「节点不超过 8 个、侧重投放流程」这类可留 | 作为「补充要求」的示例提示保留一条 |

## 8. 交互与动效

### 8.1 动效原则

- 只做**状态变化**：hover/active 底色、宽度过渡、浮层进出；
- **不做内容入场动画**（左栏折叠时内容再做 opacity/translateX 会抖动）；
- 侧栏折叠：`flex-basis/width 200ms cubic-bezier(0.22,1,0.36,1)`，`box-shadow` 同步过渡；去掉 `will-change`；
- 弹窗 160ms 淡入 + 4px 上移；快捷面板 140ms；
- 所有动画在 `@media (prefers-reduced-motion: reduce)` 下关闭。

### 8.2 交互约定

- hover 优先改底色，**不加描边、不位移**（FAB 的 scale 1.04 是例外）；
- 可点区域尽量整行可点，不用小图标当唯一入口；
- 危险操作二次确认，文案说明影响范围并给替代方案（"只想收起请用归档"）；
- 归档 = 只读 + 从列表收起；删除 = 二次确认 + 自动备份；
- 点击外部/Esc 关闭浮层；焦点管理：打开弹窗聚焦首个输入，关闭回焦触发元素。

### 8.3 跨组件通信

- 插件在宿主里有多个插槽（主面板 / 顶栏 chip / 设置页），组件树彼此独立；
- 跨树操作**不要只写 localStorage 再指望对方重渲染**；用页面内 `CustomEvent`（如 `flowpilot:set-view`）通知已挂载组件，localStorage 只做"下次启动恢复"。

## 9. 主题与深色模式

- 所有颜色令牌用 `light-dark(浅, 深)`，跟随宿主 `color-scheme`；禁止写死单一模式的 HEX；
- **主题色只旋转色相**，不改变饱和度/明度：
  - `--fp-accent` = `light-dark(hsl(H 100% 66.3%), hsl(H 100% 68%))`
  - `--fp-accent-strong` = `light-dark(hsl(H 100% 61.6%), hsl(H 100% 63%))`
  - 预设：紫 275° / 蓝 216° / 业粉 343°；自定义滑杆写 `localStorage['flowpilot.accentHue']`；
- 运行时覆盖机制（关键教训）：
  - CSS 里定义 `--fp-accent: var(--fp-accent-runtime, light-dark(#b753ff, #bb5cff))`；
  - JS 只写 `--fp-accent-runtime(-strong)` 到 `documentElement`，**不能直接覆盖 `--fp-accent`**（`.fp-root` 自己定义了同名令牌，会把 `:root` 的内联值压回去，滑杆就"不管用"）；
- 深色模式检查项：原生控件图标（日期选择器）是否变浅、阴影是否还看得见、语义色在深底上是否仍可读。

## 12. 质量门与验证方法

### 12.1 必跑命令

```bash
node tools/audit-ui.mjs --strict      # 描边预算 / 4 栅格 / 非法色 / 按钮边框 / 文案原则
node build-client.mjs && node --check client.js
node tests/client-smoke.mjs           # 客户端 SSR 冒烟 + 回归断言
node lib/selftest.mjs                 # 宿主全量自测（199 项）
npm run release:check                 # 以上打包（发版前）
node tools/verify-live.mjs --port=<GUI端口>   # 实机：新宿主/新路由是否生效
```

### 12.2 硬性预算（`tools/audit-ui.mjs`）

- 全量 `border` ≤ **24**（逐文件预算见 `docs/UI-DESIGN.md` §7），新代码默认 0；
- 非 4 栅格间距 = **0**；
- 非法 HEX = **0**（只允许 设计系统 调色板，且只在 `10-util.js` 令牌块）；
- `--dsw-alias-*` 颜色令牌 = **0**；
- 用在 `<button>` 上的类必须清原生边框；
- 文案：黑名单复述 + hint 超过 30 汉字 → `--strict` 失败。

### 12.3 视觉验证方法（避免"看起来对"）

1. 从构建产物 `client.js` 里 `grab()` 出 `CSS_BASE / CSS_FLOW / …`，拼一个最小 HTML；
2. Chrome headless `--dump-dom` 注入脚本，读 `getComputedStyle`（尺寸、圆角、底色、边框、字号、transition）；
3. `--screenshot` + PIL 采样关键像素：
   - 圆形按钮：四个角像素 = 页面底色 → 是圆不是圆角矩形；
   - 输入框：框外像素 = 分区底色、框内 = 面底色 → 没有黑边；
   - 层级：body / 卡片 / 控件三层颜色必须两两不同；
4. 深色模式用 `color-scheme: dark` 再跑一遍；
5. 结果写进回复（数值 + "✓/✗"），不要只说"已修复"。

## 13. 用户建议与决策记录（按主题）

> 以下都是本项目中由需求方明确提出、并已落地的设计意见；新改动默认遵循。

1. **少即是多**：不写不必要的副标签/说明，让布局去解释（已沉淀为 §7 原则与 audit 规则）。
2. **节点导轨不要圆角矩形**：用 **小圆形**、尺寸小一点（20px），完成节点绿色即可，颜色对比"有一点但不要太明显"。
3. **连接线要"好看"**：细（1.5px）、柔和灰、与节点圆心同轴；回流虚线细密、不双线。
4. **FAB 要真圆形**：不是圆角矩形；不要太大（40px）；**不要用强调色**，用中性面 + 次级灰图标。
5. **一个区域只强调一个操作**：「开始处理 / 继续修改」是唯一主操作，其它按钮中性但必须"看得出是按钮"。
6. **不要滥用强调色**：AI 建流程、底部操作、各处 primary 恢复为中性；黑白只留给唯一主操作。
7. **设置页每个功能一张卡**：弹窗底灰、卡片白、控件再下沉一档，三层必须能区分。
8. **AI 建流程要"一条主线"**：状态压成一行、字段头放字数、重复说明只留 footer 一处。
9. **归档放左侧栏目**：左栏常驻「已归档」栏目；业务线标题右键菜单里加「归档业务线」。
10. **视图 tab 顺序**：流程 → 今日 → 交接 → 周报。
11. **快捷面板「今日 / 交接」必须真的跳转**（跨组件树用事件，不要只写 localStorage）。
12. **完成/跳过的节点不显示"逾期"**（已完成的事不该报警）。
13. **审批意见长文本必须换行**，不能溢出/挤掉状态。
14. **日期时间输入框不要原生黑边**（统一 `.fp-dt-input` 样式）。
15. **左栏项目卡第二行不重复业务线名**（外层分组已说明）。
16. **侧栏折叠不能闪/跳**（去掉内容入场动画与 will-change，只保留宽度过渡）。
17. **图标宁缺毋滥**：文字说清楚就不加图标（底部两个按钮、文件选择按钮均去图标）。
18. **主题色滑杆只换色相**："不要在调整同一个颜色的饱和度/明度"；滑杆必须真的生效。
19. **按钮看得清**：面和底不能同色；详情分区里默认按钮要抬一档，hover 后不能"消失"。
20. **顶部 tab 顺序与右栏体验**：tab 顺序按使用频率排；右栏详情/推进要一眼看到主动作。

### 13.1 实现侧建议（做界面时可以照用的工程经验）

1. **设计值单一来源**：颜色/间距只写 `CSS_BASE`，组件只引用令牌；不要在组件里另起一套"看起来差不多"的值。
2. **先验证再交付**：改样式后用计算样式 + 像素采样证明（圆、边框、层级颜色），不要凭截图"感觉对了"。
3. **深色模式是第二套主题，不是反色**：原生控件、图标、阴影都要单独看一眼。
4. **不要用更强的颜色解决"看不出来"**：先查是不是"面和底同色"；换成抬一档底色通常就够了。
5. **强调色配额**：一屏最多一个 primary；其余用尺寸/位置/面层级区分，不用第二强调色。
6. **跨插槽通信走事件，不走 localStorage**：localStorage 只做"下次启动恢复"。
7. **动效宁缺毋滥**：删掉入场动画后 UI 会更稳；只保留宽度/颜色/浮层过渡。
8. **优先用布局消除文案**：删一句 hint 通常比加一句说明更有效。
9. **规则要能自动检查**：凡是"应该"的约定，尽量落进 `audit-ui.mjs` 或 smoke 断言，否则下一个改动就会破。

## 14. 反模式与事故复盘（真实踩过）

| 事故 | 根因 | 正确做法 |
|---|---|---|
| 滑杆拖了没反应 | `--fp-accent` 写在 `:root` 内联样式，但 `.fp-root` 自己定义了同名令牌 | 用中间变量 `--fp-accent-runtime` + `var()` 覆盖 |
| 拖滑杆像在改饱和度/明度 | 深色强调字用了 84% 饱和度 + 不同明度 | 固定 S/L，只旋色相 |
| 详情里按钮"消失" | 分区底 `surface-2`，默认按钮也是 `surface-2` | 分区内按钮抬到 `surface`；hover 用 `pressed`（不要用与分区同色的 `hover`） |
| 日期输入框黑框 | 原生 `<input type=datetime-local>` 未清 UA 边框/appearance | `border:0; appearance:none` + surface 底 + `color-scheme:inherit` |
| 深色主题出现"双圈" | `<button>` 没清原生 border | 所有 button `border:0; appearance:none`，audit 强制 |
| 快捷面板点"今日"没反应 | 跨组件树只写 localStorage，已挂载 Shell 不重读 | `CustomEvent('flowpilot:set-view')` 通知 + 下一次启动恢复 |
| 侧栏折叠闪烁跳动 | 内容入场动画 + `will-change: flex-basis,width` | 删动画、删 will-change，只留宽度过渡 |
| 节点标记像圆角方块 | 外部样式可能覆盖 `border-radius` | 内层元素画圆 + `clip-path: circle(50%)` 双保险 |
| AI 弹窗层级乱 | 同一句话写 4 遍、大绿横幅抢视线 | 状态压一行、字段头放计数、说明只留 footer |
| 卡片/分区不可见 | 卡片与容器同色（弹窗 body = 卡片底） | 弹窗 body 下沉为 `surface-2`，卡片 `surface` |
| MCP/样式令牌互相打架 | 同一设计值多处定义（令牌链） | 设计值集中 `CSS_BASE`，组件只引用令牌 |
| 文案被 audit 拦下 | 复述型 hint 超过 30 汉字 | 删到只留约束/默认值 |

其他禁止事项：
- ❌ 用 `border` 做容器/按钮/输入框分隔（预算仅留给 spinner 等例外）；
- ❌ 引入渐变、叠多层阴影、圆角/间距自由发挥；
- ❌ 直接写 HEX 或 `--dsw-alias-*` 颜色；
- ❌ 用图标代替文字解释（图标只做辅助）；
- ❌ 为"好看"加内容入场动画。
